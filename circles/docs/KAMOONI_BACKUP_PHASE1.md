# Kamooni backup preparation

This is the historical offline inventory rehearsal. The daily backup and recovery procedure is documented in the [Kamooni daily backup and restore runbook](KAMOONI_BACKUP.md).

## Inventory to verify

Record the observed platform, topology, onboarding state, source sizes, tool releases, mounts, overrides and free space in the restricted deployment ledger. Keep the live backup repository identifier, its status and credential recovery details in the protected recovery records. Use only sanitized aggregate evidence in the offline inventory.

Checked-in defaults help identify what to verify. Use runtime facts for the capture and restore recipes.

| Component | Source and evidence to inventory |
| --- | --- |
| Compose and configuration | Running project, service list, OS and Compose versions, deployed full app Git SHA, immutable image IDs/digests, ordered Compose files, working directory, config bind mounts, env-file precedence and host overrides. Include active onboarding override provenance, nginx and certificate recovery, cron/host workers and the secure recovery location for app/backend credentials. Record paths and sources here, and keep values in the protected configuration recovery procedure. |
| MongoDB | Effective app database and server, exact release, FCV, topology, mounted dbpath, logical and physical bytes, all collection/view names and counts, indexes, and the role/bootstrap recovery procedure. Scope capture to the whole `circles` DB. Base volume is `circles_mongo` at `/data/db`. |
| DID files and other app state | Resolve `APP_DIR` and its production fallbacks in `auth.ts`, plus the watchdog’s `ONBOARDING_USERS_DIR` if overridden. App mounts `/circles/users` separately from its parent `/circles`. Count files and bytes in each effective tree, record permissions and numeric ownership, and explicitly inventory server signing keys under `/circles/server` or its override. A parent-volume listing can show shadowed or stale DID files. |
| MinIO | Actual server release, data path, credentials recovery reference, configured routes and all buckets with counts and bytes. Repo defaults include `circles` (legacy upload and nginx path), `MINIO_BUCKET` for public media if set, `MINIO_PRIVATE_BUCKET` or `circles-private`, and `MINIO_VERIFICATION_BUCKET` or `circles-verification`. Inventory versioning, delete markers, lifecycle, IAM and bucket policies, object metadata/tags, object lock, and encryption/KMS dependencies. Base volume is `circles_minio` at `/data`. |
| Qdrant | Exact running release/image, single-node mode, collection and point counts, aliases, vector parameters, and effective storage, snapshot and scratch paths including overlay storage if any. Base volume is `circles_qdrant` at `/qdrant/storage`. Check `VDB_ENABLED`, `QDRANT_HOST` and the Qdrant storage/cluster overrides. |
| Target and disk | Check the physical staging path, owner, mode, absence of existing sets and unsafe links, underlying device, quotas, free bytes and inodes. Check the Qdrant scratch and snapshot destination filesystems as well. Reconcile actual sources and capacity with the reviewed inventory. Keep Restic and S3 credentials separate. |

Use the actual app image and runtime precedence to resolve `MONGODB_URI` (host/port only), `CIRCLES_MONGODB_DATABASE`, `MINIO_HOST`/`MINIO_PORT`, `CIRCLES_URL`, identity-path selectors, Qdrant config and the active onboarding Compose override. Confirm that the app reaches each observed listener on the shared Compose network and that the listener uses the inventoried data mount. Reconcile the app’s effective settings with the restricted deployment ledger before signing off. Stop for review of unknown services, alternate topology, external backends, unexpected mounts or config sources outside the supported roots. Keep credential-bearing URIs, secret env values, file contents, DIDs, object keys and app records out of the rehearsal input and shared logs.

For a later authorized inventory review, this projection on Genesis2 in a Bash shell shows running container metadata without dumping container environments or Compose interpolation. Treat an empty result or any unexpected cardinality as a stop. Where labels alone are insufficient, reconcile against the authorized deployment ledger. Use previously approved least-privilege read tools for aggregate statistics. Capture a UTC observation time with the restricted ledger and account for concurrent changes when interpreting live counts.

## Offline preflight and dry-run

Run from the root of the isolated worktree on the local Mac with Python 3.9 or later. Use a reviewed, sanitized regular inventory file outside Git. The synthetic `inventory()` fixture shows the exact schema. [Synthetic fixture](../scripts/kamooni-backup-preflight.test.py)

```bash
python3 -I -B circles/scripts/kamooni-backup-preflight.py --dry-run < /absolute/path/to/inventory.json
```

- Schema 3 requires `reviewed: true` and the evidence below. The reviewer separately verifies the protected ledger against the observed runtime and recovery records. The offline tool checks consistency within the supplied inventory.
- `runtime.services` records every running Compose service, its networks, ordered Compose files and exact container mount destinations. Record physical host mount sources, volume names or bind types, and access mode. The app routes `db:27017`, `minio:9000` and `qdrant:6333` must match observed listeners on a shared network and resolve to the selected writable data mounts. The base layout requires `circles_mongo` at `/data/db`, `circles_minio` at `/data` and `circles_qdrant` at `/qdrant/storage`, with Docker local-volume mountpoints. It also requires `circles_circles` at `/circles` and `circles_circles_users` at `/circles/users`. A named volume must have the same physical source wherever it is used. Base app, backend, nginx and cron services use `circles_webnet`. Record any reviewed layout override in the affected service’s Compose list and verify the resulting routes in the ledger.
- Include every effective Compose file under the project checkout in `config_paths`, along with the base and activation environment files, routing verifier, nginx configuration, certificate directory and Certbot webroot. Record canonical paths, numeric ownership, modes and symlink checks for those paths, all mount sources and any Qdrant writable layer in `host_paths`. For every config path, `sources.config.entries` records either a captured file or directory with device, inode and byte evidence, or a distinct protected ledger reference. Verify each reference independently against the required source and its recovery procedure. For the nginx TLS chain and private key, verify recovery or test reissuance. Keep credential values out of the inventory.
- `runtime.writers` covers Compose cron and Watchtower, host workers, webhooks and direct writers. Use `gate-and-drain` for observed writers and `verified-absent` only after checking that the class is absent. The ledger records the actual writers and how to gate them, including restart control for Watchtower. For active onboarding, supply the effective deployment ID and watchdog users root. Match the routing record and watchdog deployment ID to the effective ID, and inventory both provisioning and finalization lease collections and their active counts. Lease counts observed during inventory can be nonzero. The capture checkpoint requires a separate drain and reconciliation.
- `sources` covers MongoDB, identities, app state, MinIO, Qdrant and configuration. The identities entry ties the dedicated user mount to counts for each of the four credential filenames and confirms the complete per-account layout. The plausibility floor is 3,504 bytes per set, allowing 16 bytes each for the salt and IV, 400 for the RSA public PEM and 3,072 for the hex-encoded encrypted private PEM. Synthetic 2048-bit PKCS#1 samples measured 3,818 bytes per set. Use measured file sizes and budget archive overhead separately. Review credentials with a different format against the deployed code. App state separately identifies the server signing-key directory on the parent mount, both key filenames and sizes, and evidence that the pair matches. Keep key contents and account identifiers out of the inventory. If a required bucket, namespace or key is absent, stop for a scope decision.
- Each MinIO bucket declares its versioning state, current data object count and `current_bytes` from an independent sum of current object sizes. Record the noncurrent data version count and payload in `version_bytes`, along with all delete markers. A bucket with zero current objects qualifies if it retains versions or delete markers and reports zero current bytes. Bound current export data and metadata in `bytes`. Its offline floor is the sum of the buckets’ `current_bytes`. Budget history separately in `history_bytes`, with a floor of noncurrent payload plus 64 bytes of metadata per version or marker. Use the actual format’s conservative bound when larger. Bound the staged MinIO and config export trees, including directories and manifests, in their respective `export_inodes`. Qdrant’s `scratch_bytes` and `scratch_inodes` cover its intermediate and final service-side files. The byte allowance must be at least twice the Qdrant storage bound.
- `stage` describes `/root/kamooni-backup-staging`. Use `state: "absent"` only after checking that the final name has no filesystem entry and `/root` is private, or use `"empty"` for an existing empty directory. The checked directory must be owned by UID and GID 0 with mode `0700`. Verify the full path chain, symlinks, ACLs and private ancestry. For staging and each Qdrant storage, snapshot and temp path, record the canonical path in its namespace, backing anchor, effective `host_path`, device major/minor, raw available bytes and inodes, and remaining quota. For Qdrant, the effective host path is the most specific mount source plus the container suffix, or the writable layer plus the container path. Snapshot and temp paths must be separate from each other and avoid protected sources, including where a read-only bind appears below either root. Phase 1 rejects descendant mounts because the root capacity record does not cover them. Use `null` for a quota only after verifying that the resource is unbounded by quota. Obtain a common raw observation per device. The budget covers two copies of the actual staged exports, including the five top-level files, Qdrant’s service-side allowance, a 10 GiB reserve and a 4,096-inode reserve. The MongoDB archive uses one staged inode regardless of document count. Recheck paths, permissions, quotas and capacity in the capture window.
- `versions.capture` records observed releases and `versions.restore` the planned exact matches. The checks cover MongoDB 7.0/FCV 7.0, Qdrant 1.x, Database Tools 100.20.1, Restic 0.16.4 and valid MinIO release timestamps from 2015 through the current UTC time. MongoDB patch and Qdrant minor/patch components are limited to two digits. Verify actual release existence and compatibility separately. In `application_recovery`, match the deployed image ID, Git SHA and immutable registry or archive digest to the same three values in `test_result`. The recovery owner separately verifies the protected record named by `test_ref`, including the bytes used and the successful isolated image recovery. Rehearse the full-set restore separately with pinned backend images and the actual MinIO, MongoDB and Qdrant tools.
- The script reads inventory only from stdin, uses the local UTC clock for release timestamp bounds and emits fixed status messages. It has no subprocess calls, network client, file creation, repository check, credentials loading or Restic invocation. A successful run reports `Snapshot ID: none`. Rejection exits 1, and invalid invocation exits 2.

Run the isolated synthetic suite from the worktree root.

```bash
python3 -I -B circles/scripts/kamooni-backup-preflight.test.py -v
```
